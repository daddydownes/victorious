# Rapid-scroll Vault loop correction

At baseline `42c50d5`, a single24000px wheel step followed by29 onward140px steps bypassed the normal24% entrance threshold. The first active Vault occurred111ms into Chromium's1646ms burst and113ms into WebKit's1057ms burst, with no settling at activation. See [baseline trace](jump-before.json). This proves the entrance/quiet-handoff skip; measured child pan displacement was zero, so photo movement or an indefinite freeze is not claimed from this reproduction.

The builder now projects normalized cancelable wheel distance before native scroll. A step crossing the threshold stops at its rounded-up position and starts the existing entrance synchronously. Already-full native arrival with pending entry or recent forward intent uses the normal readiness/quiet handoff. Programmatic/restored full-view activation without new intent remains supported. Video, game, archive and all original media remain unchanged.

[Matching stress after the fix](jump-after.json) records zero active frames during the entire input burst in both engines. Activation occurs141ms after the final recorded input in Chromium and143ms after it in WebKit. [Desktop stress](desktop-stress.json) passes14scenarios: initial huge bursts, five repeated Surface→fast-bottom cycles per engine, and reversal/retry. [Phone stress](phone-stress.json) passes five rapid full-story touch loops each at390×844 and844×390, including clean Surface focus return and keyboard activation. [Six cold-load/End cases](cold-and-end.json) cover both engines, huge wheels, a2.5second delayed child and keyboard End; each finishes active at the exact viewport. A [single fast phone swipe](single-phone-fling.json) did not reach the bottom from the story start and produced no unexpected commitment.

All [eleven refresh/history cases](history.json) pass, including actual Chromium BFCache. Navigation VM16/16 (tests checkpoint `8e7f535`), deterministic integration15/15, protected game source and media37/37 byte identity pass. The root also inspects before/after screenshots. Browser wheel/touch automation is not physical-trackpad/phone certification. No forms submitted.

Five Sol-low delegates were assigned independent QA/audits/tests; root drove browsers and completed the phone harness. Harness corrections: do not wait for the intentionally lazy child at the untouched story top; sample completed activation after the corresponding rAF; explicitly place the pointer in page content before wheel input. Those were test setup/timing fixes, not product changes.
