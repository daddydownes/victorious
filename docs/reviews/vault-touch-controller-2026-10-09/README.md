## Reproduced cause

The owner clarified that moving a held finger up and down makes the scene jump. The prior controller prevented native scrolling, waited for 28px of displacement and launched a 420–640ms animation independent of subsequent finger position. Reversal started another timed transition. Earlier loading/scroll-work changes did not change that interaction model.

A controller-only regression needs no images or network: the published version moved about 72.29px for a subsequent 40px finger displacement and fails the new direct-follow assertion. In actual Chromium CDP-touch checks at 390×844/DPR3 with every photo already decoded, the published camera advanced as much as 258.26px beyond a delivered input step during arrival and 246.14px during zoom. The candidate's maximum excess is zero for both phases; displacement remains within its 6px initial intent slop and reversal follows immediately. Both candidate stationary holds have zero drift. See [touch-follow.json](touch-follow.json).

These measurements compare input-to-position behavior, not FPS or physical-iPhone performance. Chromium initially withheld small injected movements until its own touch threshold; the harness records delivered touch events and compares against those, rather than incorrectly treating withheld commands as controller input. Both versions use the same harness. Static opening setup and decoded photos isolate the mechanism; full-film journey testing is separate.

## Change and preserved behavior

Phone touch input now owns a direct position within its starting chapter. Six pixels of intent slop avoid turning a tap into a drag; subsequent delivered displacement moves the camera one-to-one in either direction. Holding still no longer advances an automatic tween. Accepted release completes the selected endpoint; small previews return to the origin. A held gesture cannot skip the overview or enter before release. Fresh dragging can interrupt a release animation from the displayed position without returning to its native anchor.

Native/uncancelable input yields ownership for both approach and zoom. Cancellation, multiple contacts, resize, visibility and exact-once handoff remain coordinated. Toolbar/layout changes rebase the held fraction rather than introducing a new motion command. Desktop wheel/key tuning remains; 540 wheel frames match the previous published controller across forward movement, reversal and repeated bursts.

The owner also requested restoration if earlier changes broke or removed something. Independent comparison of PRs #9–11 with earlier published sources found no concrete removed functionality requiring rollback. The strict new scope check permits only the entry controller: root camera, image loading, markup, CSS, original media/quality, signup, archive pan, Surface, game and hosting are preserved. Known cancellation fixes remain in place.
